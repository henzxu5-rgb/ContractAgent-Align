# 方法说明

## 任务

输入一份英文 NDA 和一条陈述，Agent 在合同里搜索、阅读，最后提交三种标签之一（Entailment / Contradiction / NotMentioned）和证据片段编号。

- 搜索用 BM25，不训练。
- 每个任务最多 6 次搜索或读取。
- 只能引用实际看过的片段。
- 合同原文和标注分开存放，模型运行时看不到标准答案。

## 想比较什么

在基础模型、SFT 起点、候选数据和训练配置都相同的情况下，只改变偏好标签的来源：一组只用 LLM Judge，一组再用标准答案核对。看两种标签训练出来的模型有没有差别。

两组最后共用 88 对候选，其中 17 对的偏好方向不同。

## 数据

- 沿用 ContractNLI 官方按合同的划分：训练 423 份、验证 61 份、测试 123 份。
- 检查了完全重复的合同，训练集里和测试集重复的一份（538 号）已排除。
- 随机种子固定为 20261015。从测试集按合同 ID 抽 20 份，每份测 17 条陈述，共 340 个任务。测试集不参与任何筛选和调参。
- 教师模型一共执行了 236 个训练任务，保留 120 条合格记录，覆盖 111 份合同，拆成 674 条 SFT 样本。

偏好数据的生成方式是：从 SFT 模型的某个状态出发，采样两个下一步动作，分别执行到底。

- 一共 400 对候选，其中有动作相同的、两个都答错的，也有平局和拒判的，都计入统计。
- 两组共同保留下来的有 88 对，覆盖 78 个任务，其中 65 对的工具调用不同。
- 候选里 67 对来自温度 0.7，333 对来自温度 1.2。换温度是为了得到更多不同的动作，不能据此推断温度本身的作用。

## Judge

Rubrics 的检查顺序是：陈述有没有判断对 → 证据是否支持、引用是否有效 → 工具用得是否合理 → 答对的前提下有没有多余调用。

只用 Judge 的一组看不到标准答案。核对的一组会结合标准标签、证据 F1、提交是否有效，以及交换 A/B 顺序后判断是否一致。两组都允许平局和拒判。

整体来看，核对流程对 77.5% 的候选没有给出明确偏好；交换顺序后有 22.5% 的判定发生变化，这里包括从 A/B 变成平局或拒判的情况。标准证据不一定穷尽所有合理证据，所以核对本身也不完全可靠。

## 训练

- 基础模型：`Qwen/Qwen3-4B-Instruct-2507`（revision `cdbee75f17c01a7cc42f958dc650907174af0554`）
- 单卡 4-bit QLoRA，rank 16、alpha 32、dropout 0.05，最大长度 4096，batch 1、梯度累积 16
- SFT：学习率 1e-4，2 轮，共 86 步
- DPO：两组都从同一个 SFT 出发，学习率 5e-6，beta 0.1，1 轮，各 6 步

DPO 的参考模型固定为 SFT，并检查了：

- 两组的初始模型和参考模型相同；
- 参考模型在训练中没有被更新；
- 训练后参数确实变了；
- 保存的模型可以重新加载。

步数很少，这是 DPO 结论有限的主要原因。

## 测试

五种设置：基础 Agent、SFT、只用 Judge 的 DPO、核对后的 DPO、基础模型直接读全文。每种都跑同样的 340 个任务。

- 全文设置的上下文上限是 16384，工具 Agent 是 4096。
- 推理 batch 上限都是 16。

主指标是三类 Macro-F1。另外还统计了：

- 各类 F1；
- 证据的精确率、召回率和 F1；
- 无效引用、工具错误和调用次数。

证据指标只在标准答案为支持或反驳的 204 个任务上算，另外 136 个"未提及"任务不计入。失败和没提交的任务都留在分母里。区间估计按 20 份合同做配对 bootstrap，重采样 1000 次。

结果：SFT 的 Macro-F1 比基础模型高 20.98 个百分点，这里面包括格式遵循和完成率的提升。核对后的 DPO 没有比 SFT 更好。

实验开始前定过继续扩大规模的条件：Macro-F1 比 SFT 至少高 3 个百分点，证据 F1 下降不超过 2 个百分点，无效引用不变多。这次没有达到，所以停在这一步。

## 限制

1. 陈述固定为 17 条，测试只有 20 份合同，只训练了一次。bootstrap 区间不包含重新训练带来的波动。
2. 没有新增人工或法律专家标注。AI Judge 和程序检查不能说明模型的法律解释是否充分。
3. 测试中途换过 GPU。基础模型、SFT 和"只用 Judge 的 DPO"的前 142 个任务在 RTX6000D 上跑；后者剩下的 198 个任务，以及核对后 DPO 的全部 340 个任务，在 RTX PRO 6000 Blackwell 上跑。模型权重、软件版本和 batch 上限都一致，但小幅差异不能当作严格的因果结论。
4. 没有单独比较"Judge"和"纯规则打分"，所以不能说明 Judge 本身比规则好。ContractNLI 是公开数据，不能排除模型预训练时见过。
5. 这是在 ContractNLI 子集上的自定义实验，不是官方榜单成绩，也不代表模型能做一般的法律咨询。
